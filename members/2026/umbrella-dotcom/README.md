### 平时如何使用 AI？

主要用在三类场景：写代码时生成思路和样板代码；遇到陌生工具或报错时快速定位问题；以及像本次任务这样，让 AI 阅读文档并辅助整理流程。AI 的输出我一般当作初稿，会自己运行、验证后再采纳，关键结论尽量回到官方文档确认。

### 如果 AI 给出的答案明显不对，你会怎么处理？

先停下来验证，而不是直接照做：把答案拆成可以单独验证的断言，用文档、最小示例或实际命令逐项核对；如果仍然对不上，就补充更多上下文（版本、报错、目标）重新提问，或者换一个提问角度，把大问题拆成小问题逐个解决。

## AI 辅助记录

### 1. 我遇到的问题

需要完成本次招新任务：按目录规范创建个人资料，并通过 Fork → 分支 → 提交 → 推送 → PR 的完整 Git 协作流程提交；其中 PR 的分支名、标题和改动文件还要通过仓库 CI 的严格校验。

### 2. 我是怎么向 AI 提问的

让 AI 先通读招新任务的 README 和模板，再按模板起草个人资料内容；同时请它梳理从 Fork 到 PR 的具体命令顺序，并解释 CI 校验规则（分支名 `member/2026/<GitHubID>`、提交与 PR 标题 `member: add-<GitHubID>`、只允许改动自己的目录）。

### 3. AI 的回答有没有直接解决？

部分直接解决：AI 完整理清了流程、起草了资料模板并解释了 CI 规则，本地的分支创建与提交也由 AI 协助完成。但推送和创建 PR 需要登录我自己的 GitHub 账号操作，AI 无法代替，这部分需要我在网页上完成。

### 4. 如果没有，我后来怎么继续处理？

按 AI 给出的步骤在本地核对分支名与提交标题，确认与 CI 要求一致后，在自己的 GitHub 账号下完成 Fork，再推送分支并对照「提交前检查」清单确认：只改动了自己的目录、包含任务一/三/四要求的内容、资源链接可访问、无敏感信息，最后向 `main` 发起标题为 `member: add-umbrella-dotcom` 的 Pull Request。
