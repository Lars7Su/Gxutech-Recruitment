# 广西大学 ACM-ICPC 集训队技术组

> 欢迎报名技术组！请通过真实的 GitHub 协作，向我们介绍你自己、你的学习方式，以及你如何使用工具解决陌生问题。

你不需要一开始就全知全能。我们更关注你面对陌生问题时的学习、验证与解决过程。

## 任务总览

| 任务 | 你需要完成什么 | 最终体现 |
| :---: | --- | --- |
| 01 | 创建个人资料，介绍自己与技术兴趣 | `members/2026/<GitHubID>/README.md` |
| 02 | 完成 Fork、分支、提交、推送与 PR | 你的 Pull Request |
| 03 | 分享一项值得参考的技术资源 | 个人资料的「技术资源」部分 |
| 04 | 记录一次使用 AI 解决问题的过程 | 个人资料的「AI 辅助记录」部分 |

## 开始前准备

请确认你已经具备以下条件：

- 可正常使用的 GitHub 账号；
- 一台可正常使用的 Windows、macOS 或 Linux 电脑；
- Git；
- 代码编辑器，例如 VS Code 或 JetBrains IDEA；
- 可正常使用的浏览器与搜索工具；
- 推荐准备至少一种 AI Agent 工具，例如 Claude Code、Codex 或 DeepSeek Harness。

> [!TIP]
> 如果此前没有使用过 Git，可以通过搜索引擎、AI、GitHub Docs 或视频教程学习。不会某项操作不影响——重要的是你如何主动找到办法，并且完成它。

## 01 · 创建个人资料

Fork 本仓库后，按下面的目录规范创建文件：

```text
members/
└── 2026/
    └── GitHubID/
        └── README.md
```

将 `GitHubID` 替换为你的 GitHub 用户名。请只新建或修改自己的目录，不要改动其他报名者的资料。

你的 `README.md` 需要包含以下内容：

**基本资料**

- 基本信息；
- 意向方向；
- 当前拥有的技术基础。

**请谈谈这些话题**

- 为什么想要加入技术组；
- 最近一次主动学习某项新东西的经历；
- 一个感兴趣的技术方向；
- 平时如何使用 AI；
- 如果 AI 给出的答案明显不对，通常会怎么处理。

可复制 [template.md](template.md) 作为个人资料的起点，再按照自己的实际情况填写。

## 02 · Git 协作

从 Fork 到 PR，建议按以下顺序完成：

```text
Fork 仓库 → Clone 到本地 → 创建分支 → 填写个人资料 → 提交并推送 → 发起 Pull Request
```

创建属于自己的分支，分支名请使用：

```text
member/2026/<GitHubID>
```

完成个人资料后，在该分支提交并推送改动，再向本仓库的 `main` 分支发起 Pull Request（PR）。提交和 PR 标题请使用：

```text
member: add-<GitHubID>
```

PR 描述中简要说明你完成了哪些任务即可。

## 03 · 展示你的信息素养

在个人 `README.md` 中加入一项你感兴趣的技术资源，并注明：

- 资源名称；
- 链接；
- 你是如何找到它的；
- 为什么认为它值得参考。

资源可以是官方文档、论文、课程、开源项目或技术文章等。重点不在资源是否热门，在于你如何检索、判断并说明其参考价值。

---

## 04 · 记录一次 AI 辅助过程

完成本任务过程中，选择一个你原本不会的问题，尝试使用 AI 辅助解决，并在个人 README 的最后简单记录：

1. 你遇到了什么问题；
2. 你是怎么向 AI 提问的；
3. AI 的回答有没有直接解决；
4. 如果没有，你后来怎么继续处理。

> [!NOTE]
> 没使用过 AI 不影响报名，但请简要说明原因，并尝试在本次任务中至少使用一次 AI 辅助解决问题。

相关答案会影响后续面试题目。我们更关注真实的问题拆解、验证和纠错过程，而不是 AI 是否一次答对。
